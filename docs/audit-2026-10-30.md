# Security, performance and UX audit — 2026-10-30

The day portfolio mode went on: anyone can sign in, lands in the demo org as a viewer, and owns
an account that can't deploy until approved. This audit looks at what that newly exposes, at
everything changed since the [2026-10-22 audit](audit-2026-10-22.md), at speed as a visitor
sees it, and at the dashboard through a visitor's eyes (phone width included).

## Findings and what was done

| # | Area | Finding | Status |
|---|---|---|---|
| 1 | Security · deps | **Next.js 16.3.8 had two critical remote-code-execution advisories** (image optimiser with SVG; `use cache` returning typed arrays) and a high one (Server Actions DoS). zod 4.6.5 could exhaust memory on oversized collections (the API validates every request with it); undici, fast-uri and fastify had smaller ones. | Fixed: next 16.4.2, zod 4.6.7, fastify 5.12.7; undici 7.30.1 and fast-uri 3.1.9 / 4.2.3 pinned as overrides. `pnpm audit --prod`: none left. Versions chosen at least about two weeks old where possible. |
| 2 | Security · abuse | **Nothing capped how many emails a day the platform sends.** With sign-ups open, a script signing up made-up addresses (5 a minute per IP allowed) would use Resend's free 100 a day in about 20 minutes, leaving no confirmations, resets, approvals or invitations for real people, and the bounces would hurt the sender's reputation. Before today the allowlist refused email sign-ups, so this was new. | Fixed: emails to addresses nobody has proven yet (sign-up, reset) are limited to 5 a day per visitor and 60 a day in all; past that the page says to try tomorrow or continue with GitHub or Google, which need no email. Integration test. |
| 3 | Security · abuse | **Analysis was open to unapproved accounts.** `POST /api/v1/analyze` downloads a repository (up to 100 MB) for any account, approved or not; the dashboard never shows it to unapproved accounts, but the API allowed it. | Fixed: needs the same approval as deploying. Integration test. |
| 4 | Security · sites | **Server-rendered sites lacked the security headers static ones get** (`nosniff`, frame and referrer policies, permissions policy) and announced `x-powered-by: Next.js`. | Fixed at the edge for every site answer; a site's own value wins. Unit test. |
| 5 | UX · demo | **The dashboard never looked at the visitor's role.** Every demo visitor (a viewer) saw Deploy latest, Roll back, Cancel, Deploy again, Approve & deploy, Open PR, Reject, Save and Delete, and each failed with a permissions error. The Environment tab, which viewers may not read, shimmered forever. | Fixed: actions the role can't take show disabled with a "read-only" hint (visitors still see what the product does); the Environment tab says why it's empty; adding, importing and deleting variables only show to admins. |
| 6 | Performance | **Every dashboard page waited for the account before asking for its own data**: two round trips to the VM (~375 ms each from India) instead of one. | Fixed: the page mounts unseen behind the opening logo, so its requests go out with the account's; it then shows from the cache. Traced: each page's data now arrives in the first round. |
| 7 | UX · phone | **An AI repair's title collapsed to "T…"** at 390 px, and **its diagnosis ran off the card's right edge** (the diff's long lines set the column's width). | Fixed: the title keeps a minimum width and the details wrap below; the card's columns can shrink, so the diff scrolls inside its box. |
| 8 | UX | **Two "Deploys today" on one screen disagreed** (4 and 1/50): the Overview tile counts the last 24 hours, the sidebar the UTC day the quota uses. | Fixed: the tile says "Deploys · 24h". |
| 9 | Performance | **The sign-in card wasn't in the page's HTML**: reading the query string with `useSearchParams` made Next.js send an empty card, drawn only once the JavaScript ran. | Fixed: the query string is read after the first paint; the card is in the HTML. Lighthouse mobile (local build) 99, first paint 0.8 s (1.1 s before). The first run's 87 / 4.0 s LCP on production was mostly a cold run (98 / 2.4 s on a second run). |
| 10 | Cost · demo | **The demo apps redeploy on every push to this repository** (they were imported from it): 4 builds and an AI repair call each time on the shared VM. | Open: the owner's call (pin them to a branch that isn't pushed, or keep them current). |
| 11 | UX · demo | **The demo apps are bare white test pages**, so their thumbnails look blank and their live sites look unfinished. | Open: restyle the fixtures, keeping the markers the smoke suite reads. |
| 12 | UX | The Node-only fixtures show their framework as "unknown". | Open, cosmetic. |

## Checked and sound

- **Every route's role check** (listed from the code): viewers can read, not change; tokens are per person and never exceed their owner's role; members' environment values are write-only.
- **GitHub Actions uploads:** RS256 only, issuer and audience pinned, 60 s clock skew, repository, workflow file and run pinned, a one-time nonce per attempt.
- **Two-step sign-in:** 10 codes a minute per IP and 10 wrong codes per account per 15 minutes (about a year to guess one).
- **From outside:** `/internal`, the gateway's health, metrics and admin routes refuse; a foreign origin gets no CORS allowance; HSTS with preload on the bare domain; the dashboard's CSP, frame and referrer policies are set.
- **The repository before going public:** no secret in any of 199 commits (gitleaks) or in any committed file; no env file, key, Terraform state or private document ever committed; deploys only from this repository's own pushes to `main`, and the deploy secrets are limited to `main`.
- **Speed:** the API's own work is 10–50 ms per call; the rest is the path to the VM. Static sites: assets cached at Cloudflare for a year (immutable), pages about 160 ms once warm. Landing page (Lighthouse mobile, production): 98 performance, 100 accessibility, best practices and SEO, CLS 0.

## Verified

Unit tests 349/349, integration 125/125 (including the authorization matrix), type-check and
lint clean, the dashboard built on Next.js 16.4.2 and rendered at 390 px and 1280 px as an
owner and as a demo visitor, with no page errors and no sideways scrolling.
